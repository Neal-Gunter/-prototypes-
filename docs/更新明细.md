## R39 · 钟楼旧主（隐藏 Boss）· 已实现（2026-10-29）

> 前几轮一直在加「主线能玩什么」。这一轮往回走 —— 回到最开始的三间房。
> 序章教的是走 / 挡 / 入阴；顶阁教的是**停手**。
> 而「停手」这件事，恰恰是完美弹反的真正门槛。

**39.1 触发：无伤走完序章（`main.gd`）**
- 新增 `_prologue_dmg0` —— 进序章那一刻的 `Game.dmg_taken`
- `_finish_prologue()` 里判 `Game.dmg_taken == _prologue_dmg0 and not Cfg.old_master_beaten`
- **为什么用 `dmg_taken` 而不是 `hp`**：hp 会被打坐回血掩盖，受击次数不会。
  「无伤」在代码里的准确含义是「一次都没被打中」
- 无伤 → `_enter_old_master()`；受伤 → 照旧进主线（这一局错过）
- 打输（玩家死）**不调** `_finish_prologue` → `prologue_done` 仍为 false →
  下次开新局还会走序章，可以再试。这是刻意留的「重试权」

**39.2 顶阁（`rooms.gd` + `main.gd`）**
- `PROLOGUE_MASTER`：`{"name": "钟 楼 · 顶 阁", "kind": KIND_BOSS, "boss": 17}`
- 单独一份常量，不并进 `PROLOGUE` —— 序章本身仍是「三间教学」
- `_enter_old_master()` 把它挂到序章 `rooms` 数组尾部，门 / 房间名 / 结算全复用
- `prologue_neighbors(i, total := -1)` 加 `total` 参数：进顶阁后 `rooms` 是 4 个元素，
  不传的话第 3 间会以为自己是最后一间（没有东门）

**39.3 钟楼旧主（`KIND_BOSS9 = 17`）**
| 参数 | 值 | 与其它 Boss 的对比 |
|---|---|---|
| HP | 20 | 最高（轮回使 18 / 符祖 16） |
| 移速 | **96** | **全场最慢**（轮回使 172） |
| 硬直条 | **190** | **全作最高**（轮回使 140） |
| 前摇 | **0.62s** | **全作最长**（普通 Boss 0.21~0.36） |
| `scale_f` | 1.55 | 全作最大 |
| 阶段 | 2 | — |

- `_windup_now()` 开头加专属分支返回 0.62 —— **必须放在 `_tier()` 之前**，
  否则二阶段 tier 变高会把前摇压回 0.21，「慢」就没了
- `_decide()` 开头加专属分支：直接 `_begin_windup(1.0)` 然后 `return`。
  **不读招、不瞬移、不远程、不防御** —— 全作唯一招式完全可预测的 Boss
- `_boss2_ai()` 的 CHASE 段加专属：慢速逼近，`dist < attack_range * 0.78` 就**停住**，
  不再贴脸 —— 贴脸会让玩家看不清抬手
- 视觉：石灰 + 铜锈的旧袍（`body` 0.145/0.132/0.118，`eye` 铜黄）。二阶段转铜橙

**39.4 存档（`settings.gd`）**
- 新增 `old_master_beaten`，存 `[lore] old_master`
- 与 `prologue_done` **分开**：后者管「序章看过没」，前者管「顶阁通关没」。
  打赢过之后，即使无伤也不再开顶阁

**39.5 台词（`lore.gd`）**
- `BOSS_LINES[17]` 三句都在讲「等」：
  战前「钟楼里只有一条规矩：别人抬手，你就等着。」
  战中「快是学不会的。慢才会。」

- **没有加残卷**：残卷是 13 条 / 五幕，是很多断言的基础，为隐藏 Boss 破例不值

**39.6 修掉两个真 bug（都是本轮自己写出来又抓出来的）**
1. **`rooms` 是只读数组**：`_enter_prologue()` 里 `rooms = RoomScript.prologue_rooms()`
   拿到的是 `const PROLOGUE["rooms"]` 的**引用**，`append()` 会失败并**中断整个函数**。
   现象：顶阁永远进不去，`room_i` 停在第 3 间，`prologue_mode` 却是 true。
   修法：`rooms = rooms.duplicate()` 之后再 append。T180 抓出来的
2. **`prologue_mode` 残留**：`_enter_level()` 没有重置它，导致「上一局停在顶阁、
   下一局进主线」时仍被当成序章。修法：`_enter_level()` 开头设 `prologue_mode = false`

## R38 · 因果 / 业力（三结局 + 魔剑）· 已实现（2026-10-29）

> 前两轮都在加「关卡能玩什么」，这一轮加的是「**你怎么打**」。
> 同样的七关，可以有三种走法 —— 而且第三种（不杀）不需要任何新按键，
> 它只需要你在那个窗口里**忍住不按**。

**38.1 业力（`game.gd`）**
- 新增 `var karma := 0` / `var spared_count := 0` / `const KARMA_MAGIC := 5`
- **正 = 魔道，负 = 天道**（这是本轮对规划稿的方向重映射，见 38.6）
- 三条来源，全部落在已有机制上：
  | 行为 | 业力 | 触发点 |
  |---|---|---|
  | 处决 | **+1** | `main._do_execute()` 成功 |
  | 普通击杀 | 0 | 不算账 |
  | 放走 | **−1** | `enemy` 的 `broken_t` 自然走完而人还活着 |
- `add_karma(n)` 夹在 ±99；`karma_branch()` 返回 0 天 / 1 人 / 2 魔；
  `karma_branch_name()` / `karma_line()` 供结算页用
- `reset_stats()` 里清零 —— 业力是**局内**变量，每局重算

**38.2 「放走」的判定（`enemy.gd`）**
- 新增 `signal spared(enemy)`
- 在 `_physics_process` 的 `broken_t` 衰减处：跨过 0 且 `not dead` 时 `emit`
- 这是本轮唯一的新判定，却**不引入任何新输入** —— 玩家原本就有「按 F 处决」这个选择，
  现在「不按」也有意义了
- 窗口长度沿用既有：普通敌人 2.0s / Boss 1.2s（`_break_posture()` 里定的）

**38.3 接线（`main.gd`）**
- 两处 `spawn` 都连 `e.spared.connect(_on_enemy_spared)`（主路径 + 镜像路径）
- `_on_enemy_spared(e)`：`spared_count += 1` + `add_karma(-1)` + 飘字「放 走」
- `_do_execute()` 成功后 `add_karma(1)`
- 三处法宝抽取改传 `Game.karma_unlocks_magic_sword()`

**38.4 魔剑（`relics.gd` + `player.gd` + `main.gd`）**
- 池子 34 → **35**（随机 32 + 影 3），剑位 12 → **13**
- `{"id": "magic", "name": "魔 剑", "need_karma": 5, "cost": "气血上限 -1"}`
- 效果：处决伤害 **×2** + 处决后回 1 点气血；代价：`max_hp()` −1
- **门槛实现刻意不读 Game**：`pick_n_biased(..., allow_karma := false)` 多一个开关，
  由 `main` 传 `Game.karma_unlocks_magic_sword()`。
  这样 `relics.gd` 仍是纯静态表，单测不必拖 autoload 进来（T178 直接调静态函数）
- 正反馈闭环：处决多 → 业力高 → 越容易遇到魔剑 → 处决更强 → 更魔。
  这是本作第一条「玩家的行为直接改变能拿到什么」的通路

**38.5 三结局与显示（`hud.gd`）**
- 结算页新增 `_draw_karma_line(c, y, with_line := true)`：

**37.2 旧影（新增 `scripts/echo.gd`）**

**37.3 轨迹录制（`main.gd`）**
- `ECHO_SAMPLE = 0.1` / `ECHO_KEEP = 40` → 保留最近约 4 秒

- `_spawn_echoes_at(pos, n)` 从轨迹里**错开起点**取段，让几只影子不重叠在同一点

**37.4 轮回使（`KIND_BOSS8 = 16`）**

## R34 · 背景音乐（BGM）· 已实现（2026-10-28）

> 三十余轮零声音的游戏，终于有声音。这一层**不引入任何外部音频素材**，

> （泛音比 1 / 2 / 2.76 / 5.40 / 8.93）叠加低吟 drone，做无缝循环，
> 贴合「正在熄灭的钟」的世界观。

**34.1 四段曲目（`music/` 目录，共约 4 MB）**

| 曲目 | 用途 | 时长 | 听感 |
|---|---|---|---|
| title | 标题页 / 终局 | 20s | 钟声最完整、最空 |
| explore | 普通房间 / 走廊 | 28s | 行进感、轻微金属回声 |

- 双 `AudioStreamPlayer`（_a / _b）交叉淡入淡出：切曲时新曲渐入、旧曲渐出，
  每帧 `move_toward(volume_db, 目标, 70*delta)`，70 dB/s 的淡变听不出接缝
- 挂载 `/root/Music`（`project.godot` 的 `[autoload]` 段）
- `play(track)`：空流守卫 + 同曲忽略；`stop()` 双路归零
- 接线 `main.gd`：标题页 `play("title")`；进房间前按场景选曲
  （Boss 房 → "boss" / 今日道劫 → "daily" / 其余 → "explore"）

- Godot 4.7 的循环属性是 `loop_mode = AudioStreamWAV.LOOP_FORWARD`
  （旧版 bool `loop` 已失效，自测 T161 注入静音 WAV 直接抓出 Invalid assignment）

**30.5 会心机制（player.gd）**

  / `RUNE_SHOT_SPEED = 620.0` / `RUNE_ULT_SHOTS = 8` / `RUNE_BLAST_RADIUS = 80.0`
- 分账规则（`_start_stage()`）：
  - 远程段：`spend_rune(1.0)`，**不扣灵力**
  - 近战段：扣灵力（13 × 0.55 ≈ 7.15），**不扣符力**
  - 符力不足：返回 false，飘「符 力 尽」，**不进入出刀状态**，符力不扣成负数

**数值为什么不是规划稿的「每秒回 0.5」**
- 0.5/秒 = 每一符要等 2 秒。一套连招（2 符）净耗 4 秒的回蓝，
  符剑会变成「站着等回蓝」的武器，管理感变成憋屈感。
- 实装 1.1/秒：一套连招耗时约 0.8 秒，回 0.88 格，净耗约 1.1 格
  → 连打四五套才需要歇一口。有管理感，但不憋屈。

- 手感依据：远程武器的安全性来自「不在敌人刀锋范围内」，

### 19b.2 镜像抄什么：武器抄三项，法宝只抄「厚」

`enemy.gd` 新增 `make_mirror(wid, relics_n)`。设计原则是**抄 Build 的形状，不抄 Build 的效果**：

| 抄什么 | 怎么抄 | 玩家读到的差别 |
| - | -- | -- |
| 射程 | `attack_range = 152 × reach_mul` | 长枪镜像 220 > 剑 152 > 双刀 134 |
| 出招速度 | `windup / recover ÷ speed_mul` | 双刀镜像 0.35s < 剑 0.44s < 长枪 0.54s |
| 伤害 | `dmg += dmg_add` | 长枪镜像独高一档（2），剑与双刀 1 |
| 法宝数量 | 每 2 件 +1 血、每件 +6 硬直上限 | 6 件法宝的镜像：血 3→6、硬直 113→149 |

法宝的**具体效果不逐件还原**（12 种法宝逐件抄是一轮都装不下的大工程，
而且「敌人也吃飞剑流质变」会把平衡打穿）——镜像只表达「你攒得越多，它越厚」。
外形走 R14 记忆回响的暗色剪影，眼睛与轮廓光用玩家那把武器的色相：
剑影偏蓝、枪影偏金、双刀影偏红，一眼能认出「这把是你的」。

## R19a · 序章「钟楼」 · 已实现（2026-10-27）

> R19 原本是三合一（序章 + 心魔境 + 无相），内容量最大。
> 按「一轮只改一件事」拆开：**本轮只做序章，心魔境与无相挪到 R19b。**

### 19a.1 为什么要序章

新玩家第一次打开，`_confirm_weapon()` 直接把他送进第 1 关「镇钟廊」——
**一格教学都没有**。而此时剑意交锋、护体罡气、阴阳走位三套规则是**同时生效**的。

结果就是：玩家第一只怪打不过，而且不知道该练什么，因为没有任何一个安全的地方让他单独试一个动作。
序章要做的就是「一块只有一件事的空地」。

### 19a.2 三间房，一层一件事

`rooms.gd` 新增 `const PROLOGUE`，用了一个新字段 `"fixed"`：

```gdscript
{"name": "钟 楼 · 一 层", "col": 0, "row": 0, "kind": KIND_BATTLE, "wave": 1, "fixed": [0]},
{"name": "钟 楼 · 二 层", "col": 1, "row": 0, "kind": KIND_BATTLE, "wave": 2, "fixed": [0, 0]},
{"name": "钟 楼 · 三 层", "col": 2, "row": 0, "kind": KIND_BATTLE, "wave": 1, "fixed": [11]},
```

以前刷怪只有随机池（`wave()` 抽池 + 精英替换 + 变奏叠加）。教学房**不能随机** ——
第一层如果抽到丹修自爆，教的就不是「挥刀」而是「躲爆炸」了。
所以 `_spawn_room_content()` 看到 `fixed` 就照单生成，跳过池子、跳过精英、跳过变奏。

| 层 | 教什么 | 刷什么 | 为什么是它 |
| - | -- | -- | -- |
| 一 | 移动 + 攻击 | 1 只道兵傀儡（`fixed: [0]`） | 最笨的怪，让它不还手也打不死人，只当沙包 |
| 二 | 剑意交锋 + 格挡 / 护体罡气 | 2 只道兵傀儡（`fixed: [0, 0]`） | 两只才会「同时抬手」，才有得选：撞刀还是挡 |
| 三 | 入阴 / 还阳 | 1 只怨灵（`fixed: [11]`） | 怨灵只在阴界可见 —— 不打进去就永远打不到，逼玩家学会 Q |

### 19a.3 「前尘残影」说三句

`lore.gd` 新增 `PROLOGUE_LINES` + `prologue_line(i)`：

```gdscript
const PROLOGUE_LINES := [
	"先学会走。前面那只道兵不会还手，斩了它。",
	"它抬手的时候你也抬手。刀撞刀，叫剑意交锋；挡下来，罡气会涨。",
	"它不是死了，是躲进了阴界。入阴（Q / 摇杆上推），再斩它一次。",
]
```

说话人标签是 **前 尘 残 影**，不是主线里的「残影引导者」——
序章里说话的是**前世的自己**，不是 NPC。这个身份差在 R16 的身份钩子里已经埋好了。

台词仍然走 `Cfg.seen_lines` 的 `"prologue:%d"` 键：**首次完整显示 5 秒，重开只显示 3.2 秒**，
和主线引导台词同一套规则。

### 19a.4 序章是「一条线」，不是箱庭

`prologue_neighbors(i)` 只连前后两间：

```gdscript
if i > 0: out["west"] = true
if i < PROLOGUE["rooms"].size() - 1: out["east"] = true
```

`_next_room()` 在 `prologue_mode` 下按 `room_i + 1` 线性推进。于是序章**天然没有**：

- 岔路（稳路 / 险路）—— 新玩家还不会判断「哪条划算」
- 事件房（宝箱 / 商人 / 陷阱）—— 三个都要求先懂经济
- 法宝三选一 —— `_resolve_room_clear()` 在 `prologue_mode` 下直接返回，不发奖励卡

### 19a.5 只教一次，且不占主线进度

`settings.gd` 新增 `var prologue_done := false`，存到 `[lore] prologue`。

```gdscript
# main.gd · _confirm_weapon()
if not Cfg.prologue_done and not daily_mode:
	_enter_prologue()
	return
```

- 老存档：`prologue_done` 读出来是 `false`（新键，旧档没有）→ 会进一次序章。这是有意的：
  老玩家也没被教过。
- 打完：`_finish_prologue()` 置 `true` 并 `save_cfg()`，之后新开档直接进镇钟廊。
- **不占主线进度**：三层打完 `level` 仍是 0，`_room_name` 回到 `镇 钟 廊`。
  序章是「第 0 关」，不是「第 1 关之前的一段」。

### 19a.6 顺手修掉的：两块面板压在一起

## R18b · 武器专属绝招 + APK 触屏修复 · 已实现（2026-10-27）

> 两件事，都是「让已有的东西真的生效」，没有加新系统。
> ① 把 R18 按边界挪出去的专属绝招做完；② 修掉用户报的 **APK 点不动屏幕**。

### 18b.1 修 APK 触屏锁死（用户报的 bug）

**现象**：安卓装上之后，点屏幕没有任何反应，连开始都点不动。

**根因**：触摸层把「收不收触摸」和「画不画按键」绑成了一件事：

```gdscript
# 旧代码
visible = showable
set_process_input(showable)   # ← 这里
```

`showable` 来自 `Cfg.touch_ui`。一旦它存成 `false`（玩家在设置里关过按键，
或者旧版本的存档），`_input` 整个被停掉 —— 于是**连设置页都点不开**，
再也无法把按键打开，永久锁死。

**修法三层，缺一不可**：

1. `settings.gd` 新增 `is_touch_only()`；触屏设备在 `load_cfg()` 里强制 `touch_ui = true`
   —— 配置再也关不死唯一的输入方式。
2. `touch.gd` 把 `can_touch`（能不能收触摸）与 `visible`（画不画按键）**拆开**：
   `_input` 始终开启；按键被藏起来时，**任何一次点击先把它叫回来**再返回。
3. `touch.gd` **自愈**：只要真的收到 `InputEventScreenTouch`，就认定这台设备能触屏，
   不依赖 `OS.has_feature("mobile")`。导出配置判错也不会把玩家锁死。

验证（`tools/_touch_probe.gd`，两种设备各跑一遍）：

| 场景 | can_touch | 藏起按键后还能收触摸 | 点一下能叫回来 |
| -- | -- | -- | -- |
| 模拟移动端（`--touch`） | true | ✅ | ✅ |
| 桌面端（无触摸） | false | —（本来就不该有） | — |

### 18b.2 绝招此前完全没有伤害

`player.ult_burst` 这个信号**从头到尾没有任何接收者**：

```gdscript
signal ult_burst(pos: Vector2, radius: float, dmg: int)
...
ult_burst.emit(global_position, ult_radius(), ULT_DMG)   # 发出去，没人接
```

所以「剑气纵横」一直只有动作、音效、震屏和特效，**敌人血条一动不动**。
和 R18 抓到的「凝罡·开山没有伤害」是同一类 bug：信号发出去，没人消费。

修法：`main` 接上 `ult_burst`，并新增 `ult_strike`（矩形刀路），
两条都走 `_ult_hittable()` / `_ult_hit()` 统一结算：

```gdscript
player.ult_burst.connect(_on_ult_burst)
player.ult_strike.connect(_on_ult_strike)
```

### 18b.3 三把武器各一种形态

消耗（46 灵力）与总伤害（6）**完全相同**，只有形状不同 —— 一轮只改一个手感变量，
这样「哪把武器更适合我」的答案来自形状，而不是数值大小。

| 武器 | 绝招 | 形态 | 段数 × 伤害 | 判定 | 教什么 |
| -- | -- | -- | -- | -- | -- |
| 单 手 剑 | 剑 心 · 一 线 | 一道贯穿直线 | 1 × 6 | 矩形 560×84 | 站定、瞄准、一刀到底 |
| 长 枪 | 枪 出 如 龙 | 三段推进突刺 | 3 × 2 | 每段 190×58，逐段前冲 300 | 距离就是伤害，往前压 |
| 双 刀 | 双 生 · 旋 刃 | 原地旋风 | 6 × 1 | 半径 132 圆，六次脉冲 | 贴脸、多段、叠护体罡气 |

实现要点：

- `weapons.gd` 每把武器多一个 `ult` 字段（`id` / `name` / `shots` / `dmg` / `gap` /
  `len` / `thick` / `radius` / `lunge`），`ult_of(id)` / `ult_name(id)` 取用；
  没配置时兜底成老「剑气纵横」（环形 210）。
- `player.gd` 用 `_ult_begin()` / `_ult_tick()` / `_ult_fire_one()` 三段调度：
  第一段立即出手，之后按 `gap` 排队，`_ult_total_time()` 决定硬直多久。
- 枪的每段都 `velocity.x = dir * lunge`，位移本身就是这把武器的语言。

### 18b.4 直线刀光与判定同形（`fx.beam`）

以前直线招用的是大圆环特效（`fx.ring` 半径 = 长度的一半），**看到的范围比打到的范围大一圈**。

## R18 · 精英怪 + 行为变奏（第一个「这一只不一样」的敌人层）· 已实现（2026-10-27）

> **前置**：R11–R17 把战斗、Build、叙事、命名都铺完了，但四关六房的敌人全是同一个模子 ——
> 玩家进第二关时已经不需要「看」，只需要「重复」。本轮把差异长在**敌人**这一侧。
>
> **边界（照《内容扩展总纲》§R18 执行）**：本轮**只做精英怪 + 行为变奏**，
> 三把武器的**专属绝招挪到 R18b**。理由写在总纲里：一轮只改一个手感变量，
> 否则「敌人变难」和「玩家变强」同时上线，就分不清该归功于哪个改动。
> 所以本轮验收标准是：**敌人变难了，但玩家的操作手段一点没多**。

### 18.1 六种精英（`enemy.gd` kind 8–13）

都不是 Boss：不进 Boss 血条、不锁门、不播 Boss 台词。它们只是「杂兵里长歪的那一只」。

| # | 精英 | 界 | 气血 | 罡气 | 核心招式 | 设计意图 |
| - | --- | - | -- | -- | ---- | ---- |
| 8 | 剑修傀儡 | 阳 | 8 | **120** | 剑阵（范围震波）+ 双持飞剑两连发 | 罡气 120：平砍 10 刀都推不动 → 必须用**凝罡·开山**破罡 |
| 9 | 符修 | 阳 | 5 | 40 | 扇形贴符齐射（3 张，带夹角） | 远程压制 → 逼玩家**入阴换线**绕后 |
| 10 | 丹修 | 阳 | 6 | 60 | 炼丹回血 + 近身点炉自爆 | 拖不得，拖久了它自己炸（且炸得到你） |
| 11 | 怨灵 | **阴** | 4 | 30 | 阴界追击 + 隔界飞刺 | 锁在 `YIN_DEPTH = 0.88`，阳界**既看不见也打不到** |
| 12 | 纸人 | 两界 | 2 | 10 | 每 8 秒剪一个分身 | 教玩家用**剑气纵横**清场，别单点 |
| 13 | 尸傀 | 阳 | 12 | 100 | 读招格挡 + **不可格挡**抓取 | 用取消窗口骗招；硬拼会被抓 |

- 精英护体罡气单独一张表 `ELITE_POSTURE`（覆盖默认的 `max(55, hp*8)`）——
  因为「罡气厚不厚」和「血多不多」是两件事：剑修血只有 8 但罡气 120，尸傀血 12 罡气 100，
  纸人血 2 罡气 10。**血是耐久，罡气是破防门槛**，两者拆开才能做出六种不同的解法。
- 剪影各自成形（`_draw_elite`）：剑修=悬剑环、符修=灯笼符、丹修=炉膛红、怨灵=青环幽体、
  纸人=竖纸条、尸傀=肋骨绿。脚下多一圈精英光环，玩家一眼知道「这只不一样」。
- 精英有**自己的罡气条**（小条，画在脚下），不跟 Boss 抢 HUD。
- 精英名字只在**第一次遇见这一种**时，于它头顶浮一次（`_reveal_elite_name`）。
  记录走 `Cfg.seen_lines` 的 `elite_<kind>` 键，**不新增存档字段**；见过就不再浮。
  这一条是为了让「剑修傀儡 / 符修 / 丹修 / 怨灵 / 纸人 / 尸傀」六个名字真的能被玩家学到 ——
  否则它们只活在代码的 `ELITE_NAMES` 里，玩家永远不知道自己在打什么。

### 18.2 五种行为变奏（叠在普通杂兵身上）

不是新怪，是给已有杂兵加一层「脾气」—— 让路过时也值得看一眼。

| 变奏 | 徽记 | 效果 | 玩家对策 |
| -- | -- | -- | ---- |
| 护 盾 | 六边形 | 额外 30 点护盾，每刀磨 10 点（3 刀破），**停手 4 秒回满** | 连续压制，别打一下就跑 |
| 召 唤 | 三点 | 每 8 秒召一只帮手 | 先杀它，否则越打越多 |
| 自 爆 | 倒三角 + 收紧环 | 贴身 96 内点炉，**2 秒**后炸 | 2 秒内砍一刀就打断（见 18.3） |
| 读 招 | 一只眼 | 玩家出刀时 55% 概率提前格挡（CD 2.8 秒） | 假动作骗格挡，再打真空期 |
| 狂 暴 | 三根刺 | 血量 ≤30% 攻速 ×1.5 | 留爆发收尾，别留残血 |

- 徽记是**形状 + 颜色双编码**，不是纯色点：六边形 / 三点 / 倒三角 / 一只眼 / 三根刺。
  暗背景和小尺寸下纯色点读不出来，形状能读出来；色盲玩家也能靠形状分。
- 自爆变奏额外画一个**越收越紧的倒计时环** —— 玩家不需要读秒，靠环的收缩速度就能判断还剩多久。

### 18.3 可处决窗口：`FUSE`

自爆变奏点炉后进入 `FUSE` 状态，持续 `FUSE_TIME = 2.0` 秒。这个状态：

1. **`can_execute()` 返回 true** —— 处决第一次有了实际战术用途，不再只是演出；
2. 被砍中立刻 `_fuse_canceled = true` 并转 `STAGGER` 1.3 秒 —— **打断成本极低**，
   这是故意设计的：它给你一个「看见危险 → 冲进去砍一刀」的正反馈；
3. 炸出来是真的疼（范围伤害），所以不理它的代价也够高。

设计上这是一次「**用敌人的威胁教玩家进攻**」，而不是用敌人的血量教玩家耐心。

### 18.4 关卡门槛池（`rooms.gd`）

```gdscript
const ELITE_POOL := [[], [8, 9], [8, 9, 10, 12], [8, 9, 10, 12, 11, 13]]
const VARIANT_POOL := [[], [1], [1, 2, 3], [1, 2, 3, 4, 5]]

```

- **第一关一只精英都没有** —— 第一关的任务是教基础操作（拼刀 / 格挡 / 二段跳），
  精英进去只会把教学关变成考试关。
- 第二关只开剑修 / 符修（最直白的两种：一个考破罡，一个考换线）。
- 第三关加丹修 / 纸人（考节奏与清场），第四关全开（含阴界专属的怨灵）。

### 18.5 纸人分身的接线

分身复用既有的 `summon` 信号，`main._on_enemy_summon(pos, count, src)` 按 `src.kind` 分流：

```gdscript
if src != null and src.kind == EnemyScript.KIND_ZHIREN:
    var m := _spawn_enemy(EnemyScript.KIND_ZHIREN, pos)
    m.make_mini()          # 血 1、不再召唤、不点炉
```

`make_mini()` 把 `_elite_cd` / `_summon_cd` 直接顶到 99 秒 —— **不让分身再分身**，
否则一个纸人能在 30 秒内把房间塞满。

### 18.6 顺手修掉的一个真 bug（重要）

做剑修傀儡时发现：**凝罡·开山（蓄力斩）此前一点伤害都没有**。

原因：`player._fire_heavy()` 会把 `atk` 清成 `ATK_NONE`（因为蓄力斩不走连招表），
而 `main._combat_checks` 只判 `attack_rect()` —— 于是 `heavy_rect()` 从来没被任何地方消费。
表现为「蓄力斩有动作、有音效、有屏幕震动，但敌人血条不动」，而且很难在正常游玩中发现，
因为玩家会以为是自己没打中。

修法：`_combat_checks` 加第 1.5 段，在普通攻击扫描**之前**单独判一次 `heavy_rect()`，
命中后走 `hurt() + add_posture(max*HEAVY_POSTURE_FRAC) + add_stagger(40)`。
这个 bug 是 R11 引入蓄力斩时就存在的，一直到 R18 才被抓出来。

## R16 · 残卷四幕 + 身份钩子（叙事层收束）· 已实现（2026-10-27）

### 一、残卷四幕重编（12 条 → 4 幕 × 3 卷）

## R15 · 箱庭补完（环境叙事 + 2.5D 纵深）· 已实现（2026-10-27）

> 前置：R10 把每关切成 3×2 个房间，但**房间与房间长得一模一样** —— 换房只是换一波敌人。
> 玩家走完一关，记不住自己去过哪儿。本轮不加任何新机制，只让**每一间房自己讲一句话**。
> 状态：**已实现**。`tools/selftest.gd` 全量回归 PASS=56 / FAIL=0（含 T52–T56），见 `自测记录_R15.log`。

### 一、按房型摆静物：房间第一次「有内容」

`world.set_room_env(kind, tier, level)` 把「房型 + 前后层 + 关卡」一次性交给世界层，
`_draw_env()` 按 `room_kind` 分发：

| 房型 | 静物 | 想说的话 |
|---|---|---|
| start（入口） | 后墙一排竖刻痕 + 靠地的断剑 + 石台残灯 | 有人在这儿数过日子，兵器坏了，灯快灭了 |
| chest（秘藏） | 一具靠箱而坐的骸骨（腿伸开、头低着） | 开箱开到一半就死了 |
| trap（陷阱） | 半透明受害者残影（低头、垂手、脚下有暗痕） | 他一直踩在同一个地方 |
| shop（商队） | 负匣人剪影（背上的大匣子有铜扣、兜帽下两点光、手杖） | 有人在阴影里等你拿灵魂换东西 |
| boss（门厅） | 残影引导者（见下） | —— |

- **关键约束：静物不改任何判定**。全部是 `_draw()` 里画出来的，不生成节点、不进碰撞、不占更新预算。
- 刻痕特意落在**两个壁龛之间的实心砖面**上 —— 第一版画在壁龛黑洞里，等于白画（见「三、偏差」）。
- 所有静物都遵循同一条打光逻辑：**先压暗底，再补一道亮边**。单色画在深色地面上会直接糊掉。

### 二、2.5D 纵深：伪楼层 + 落闸内收

**(1) 伪上下层（只在关卡三「玄铁墓道」成立）**

单层网格要读成两层，靠的是「同一间房在 row 0 / row 1 摆不同的东西」：

| 层 | 对应 row | 摆什么 | 视觉暗示 |
|---|---|---|---|
| 上排（偏里） | row 1 → `tier 0` | 后墙两具横置**铁棺**（铆钉 + 棺盖中缝 + 缝隙里的磷光） | 上面还压着一层 |
| 下排（偏外） | row 0 → `tier 1` | 近处地面散落**断铁链**（交叠链节 + 翘起的断口 + 旁边掉的散链） | 下面还有一层 |

> 这里踩到一个真 bug：`_draw_pseudo_ground()` 一开始和铁棺写在同一个函数里、画在 `_draw_floor()` **之前**，
> 结果整片被地板盖掉 —— 截图里完全看不见。现在拆成「铁棺（墙面，floor 前）/ 断链（地面，floor 后）」两个函数。

**(2) 落闸内收（Boss 房）**

`fg.set_squeeze(1.0)` 时前景层做三件事，让「门关上」变成可感知的空间变化：

1. 近景石柱的有效范围 `EDGE_W × 1.6`，更多柱子进入画面
2. 所有近景道具向画面中心**拽 11%** —— 只加宽不移动的话几乎看不出差别
3. 左右各压 118px 暗边，把可视区「夹」出来

> 118px 是算过的：玩家活动区 `ROOM_X0..ROOM_X1`（200..1100）映射到屏幕约 140..955，
> 所以暗边压不到战斗区。内收随 `_set_gates()` 即时生效，配合落闸音效与震屏，读作「砸下来」而不是「渐变」。

**(3) 近景垂链**

关卡三下排额外叠一层 `PAR = 1.55` 的密垂链（比常规 1.26 更快滑过）。
近景链本身接近全黑，**必须靠一圈更亮的轮廓光才读得出来** —— 所以 `_hanging_chain()` 新增
`rim` / `wide` 两个参数，近景链的 rim 拉到 2.6 倍。

### 三、残影引导者：一个只说一句话的淡影

- 只在 **Boss 房**出现（`_guide_target = 1.0`），其余房间 `_guide_target = 0.0`。
- 进房后**淡入约 0.7 秒**（`move_toward(delta × 1.45)`），站定 **1.5 秒**才开口。
  - 先让它「站住」再说话 —— 进房瞬间就弹字，玩家还在看闸门，看不到它。
- 建言按关卡取（`LoreScript.guide_line(level)`，4 关 4 句），走 `Cfg.seen_lines`：**二周目只给省略号**。
- 它给的是**方向暗示**，不是答案：

| 关卡 | 引导者的话 | 指向 |
|---|---|---|
| 一 | 它不回头。你打它背后。 | 绕背 |
| 二 | 它的刀有两段。第二段才是真的。 | 别在第一段拼刀 |
| 三 | 门开的时候，别站在门口。 | 通关瞬间的站位 |
| 四 | 别数你砍了几下。数它还剩几次能站。 | 打架势而不是打血 |

> 它是「上一个走到底的人」留下的一点残响 —— 所以它**只提示，不解释**，也永远不会告诉你它自己是谁。

### 四、偏差与取舍

## R13 · 圣物位次 + 飞剑轴（暖雪内核）· 已实现（2026-10-27）

> 前置：R12 让三把武器有了不同的连招，但遗物仍然是「见一件拿一件」的加法堆叠 ——

### 一、三位次：遗物第一次有了「容量」

- 刃 / 壁 / 灵 三个位次，**每位 3 格**（`RelicScript.SLOT_CAP`），遗物按本位次归位。
- 位次满了，奖励页不会直接吞掉你选的那件 —— 而是切到**替换页**：把该位次现有的 3 件摆成卡，选一件弃掉。
- 这条规则把「拿什么」变成「换什么」：后期每一次三选一都在问「这件值不值得挤掉一件」。

| 位次 | 容量 | 池内件数 | 装满后 |
|---|---|---|---|
| 刃 | 3 | 7（含 3 件飞剑类） | 流派 **剑修**，全段架势压制 ×1.2 |
| 壁 | 3 | 5 | 流派 **壁守**，精准格挡窗口 +0.04s |
| 灵 | 3 | 5 | 流派 **灵御**，灵魂获取 ×1.2 |

> 三个位次的总容量 9，一局能拿到的遗物远多于 9 —— 所以替换是常态，不是意外。

### 二、跨位联动：飞剑流

- 条件：**刃位有飞剑类** + **灵位至少 2 件灵魂类** → `player.is_flying_build()` 成立。

### 三、飞剑轴：不加按键的远程

- 实体复用 `projectile.gd`，新增 `setup_sword()` 与剑形绘制；穿云让它**穿透**（同一只敌人只结算一次）。

## R12 · 连招模组层（亡灵杀手 × 灰烬之国）· 已实现（2026-10-27）

> 前置：R11 已把「架势」做成双向压力条，但玩家能做的只有「砍三刀 / 挡一刀」——
> 三把武器只在数值上不同，手感完全一样。本轮不加新关卡、不加新 Boss，只改**怎么出刀**。
> 状态：**已实现**。`tools/selftest.gd` 全量回归 PASS=45 / FAIL=0（含 T41–T45），见 `自测记录_R12.log`。

### 一、核心改动：段位表从「全局一张」变成「每把武器一张」

R11 之前，`player.gd` 里有一张全局 `STAGES`（3 段），三把武器共用，只在 `reach / speed / dmg / stam` 四个倍率上分叉。
R12 把这张表搬进 `weapons.gd` 的 `combo` 字段，**每把武器一套**，并且每段自带动作标签、架势压制、取消窗口：

| 字段 | 含义 |
|---|---|
| `wind` / `act` / `rec` | 抬刀 / 判定 / 收刀时长（秒，实际会除以攻速） |
| `dmg` | 本段基础伤害（再叠加武器 `dmg` 修正与遗物） |
| `w` / `h` | 刀锋判定框尺寸 |
| `stam` | 本段耐力消耗（R12 起按段给，不再用三个全局常量） |
| `tag` | 动作标签：`slash` 斩击 / `thrust` 突刺 / `spin` 回旋 |
| `posture` | 架势压制，**占敌方架势上限的比例** |
| `cancel` | 取消窗口，收刀进行到该比例后可被闪避 / 格挡打断 |

三把武器因此有了**结构差异**（不只是数值差异）：

| 武器 | 段数 | 每段标签 | 压制总量 | 取消窗口 | 身份 |
|---|---|---|---|---|---|
| 单手剑 | 3 | 斩 / 斩 / 斩 | 0.21 | 30% / 32% / 35%（最早） | 容错：打完能退 |
| 长枪 | 3 | 突 / 突 / 突 | 0.25 | 72% / 74% / 78%（最晚） | 空间：靠距离，不靠贴身 |
| 双刀 | **4** | 斩 / 斩 / 旋 / 旋 | **0.44**（= 剑 × 2.10） | 55% / 58% / 62% / 65% | 压制：砍不死，但能砍到破绽 |

> 双刀从 3 段扩到 4 段，是把「多段」本身当成武器特性：段数多 → 架势压制总量高 → 更容易逼出「破绽」。
> 代价是单段伤害低（`dmg_add = -1`，最低 1）且刀锋最短（0.88），所以它**必须贴着打**，风险最高。

### 二、取消窗口（本轮手感核心）

- 新增 `player.can_cancel()`：仅在 `ATK_RECOVER` 阶段、且 `atk_t >= rec × cancel` 时为真。
- 新增 `player._cancel_attack()`：清空段位状态、记录收刀时刻（**不给完美拼刀资格**，避免「取消→立刻重砍」刷完美）。
- 在 `_physics_process` 里，取消窗口一开就检测 `dash` / `guard` 输入，命中即打断后摇：
  - 按闪避 → 直接进冲刺（`_start_dash`）
  - 按住格挡 → 直接进举盾姿态
- 结果：**剑可以「砍一刀就退」，枪必须站完收刀**。这是三把武器在「被打断」这件事上的最大差别，也是新手最容易感知的差别。

### 三、长枪的两个专属机制

- **距离惩罚**：`player.attack_damage(target_pos)` 新增目标位置参数；若 `|dx| < 52`（`SPEAR_DEAD_ZONE`），伤害 -1（最低 1）。
  语义：枪杆贴脸没有杀伤力，长枪必须「用枪尖打人」。这直接惩罚「贴脸无脑平A」。
- **自动追击**：`_start_stage()` 里若前方 `190px`（`SPEAR_LUNGE_RANGE`）内有敌人，出刀前冲力 ×1.85（`SPEAR_LUNGE_MUL`）。
  只给前冲加力、**不做索敌转向**——降低操作门槛，但保留玩家的方向决策（对应设计里「自动锁定但保留手动决策」）。
  实现上由 `main` 注入 `player.enemy_provider`（`Callable` 返回 `enemies`），避免 `player` 反向依赖 `main`。

### 四、与 R11 架势的咬合：命中也能涨敌方架势

R11 里敌方架势只有一条涨法——完美弹反（+40%）。R12 补上第二条：**连招压制**。

- `main._combat_checks()` 命中分支新增 `e.add_posture(e.max_posture * player.attack_posture_frac())`。
- 也就是说：**拼刀流**（完美弹反）和**压制流**（连段）现在都能逼出破绽，只是节奏不同——
  拼刀是「一次高风险高回报」，压制是「持续投入、稳定累积」。
- 同时给敌方架势加了**回落**（`enemy._decay_posture()`）：停手 `2.2s`（`POSTURE_HOLD`）后按 `16%/s`（`POSTURE_DECAY`）回落，命中即重置计时。
  > 没有回落的话，架势只增不减，任何武器打久了都能破防，双刀的「压制」优势就消失了。回落让「压制」变成**需要维持的东西**。

### 五、动作标签化（延展项）+ 三件标签遗物

- `player.attack_tag()` 对外暴露当前段的标签，遗物不再只认武器，而是认「这一段是什么动作」。
- 遗物池新增 3 件，各补一个套系的第 4 件（套系仍以 3 件触发质变）：

| 遗物 | 套系 | 效果 |
|---|---|---|
| 回 锋 | 刃之套 | 「回旋」段架势压制 +45%（双刀第三、四段） |
| 桩 步 | 壁之套 | 「突刺」段取消窗口提前 30%（长枪收刀不再干站着） |
| 余 音 | 灵之套 | 「斩击」段命中额外 +2 灵魂 |

> 这是「构筑围绕动作」的最小验证：桩步让长枪的短板（收刀晚）被遗物补掉，形成「武器 × 遗物」的乘法而不是加法。

### 六、HUD

- 攻速条下方新增一行：`段位/总段 · 动作标签`（例 `3/4 · 回 旋`）。
- 取消窗口一开，整行转绿并追加「可取消」——这是玩家判断「现在能不能撤」的唯一提示。
- 只在出刀期间显示，不常驻，避免 HUD 噪音。

## R14 · 箱庭叙事层（地图 / 故事 / 人物）· 已实现（2026-10-27）

### 一、故事框架

主角每死一次，玄界就把他「重录」一次——所以能无限重来，但每次重来世界更暗一分。

| 系统现象 | 叙事解释 | 来源 |
|---|---|---|

| 12 条 lore 碎片 | 是「上一次轮回」留下的记录 | 法环碎片叙事 |

**四关叙事四幕**（补充关卡二命名：断剑阶 / 残钟阶）：

| 关 | 现名/建议名 | 叙事功能 | 视觉母题 |

## R9 · 全盘 2.5D 大改（2026-10-26）

**这一轮做了什么**
  
不是给 2D 贴一层投影，而是给「空间」补上第三根轴：
  
**每个角色、每块石头、每片碎屑都有一个深度 z ∈ [0,1]（0=贴镜头，1=贴后墙）**，
  
z 同时决定「画多大 / 画多高 / 谁盖住谁 / 打不打得着」。
  
逻辑层仍然是纯 2D 的 `(x, y)`，深度只在渲染与判定边界上生效——
  
所以既拿到 2.5D 的观感，又没有引入 3D 引擎与物理。

**① 新增深度投影内核**（新增 `scripts/space.gd`，纯静态，无状态）

- `DEPTH_SPAN = 104`：z 从 0 到 1，屏幕上抬 0→104 px。
- `SCALE_NEAR = 1.06` / `SCALE_FAR = 0.76`：近大远小。
- `LANE_TOL = 0.30`：深度差超过 0.30 就判定为「不在同一条命线上」，打不着。
- 接口：`clamp_z` / `scale_of` / `lift` / `z_order`（z_index 20→0）/ `shade` /
    
  `shadow_alpha` / `shadow_scale` / `dim` / `back_off` / `lane_ok` / `apply_draw` / `shadow_pos`。
- `apply_draw(node, z)` 内部就是一句
    
  `node.draw_set_transform(Vector2(0, -lift(z)), 0.0, Vector2(s, s))`，
    
  以「脚底原点」为轴心整体缩放 + 上抬，角色因此永远站在自己那一层地面上。

**② 角色有了深度**

- `player.gd`：新增 `depth`（初始 `PLAYER_Z = 0.34`）、`_depth_fx`；
    
  每帧按 `depth_in` / `depth_out` 输入以 `MOVE_SPEED = 0.90`/秒 平移深度，
    
  `z_index = z_order(depth)` 实时重排，`_draw()` 首行套 `apply_draw`，
    
  影子按 `shadow_alpha(depth)` 淡出。`respawn()` 复位到 0.34。
- `enemy.gd`：新增 `depth`（初始 0.55）与 `_update_depth(delta)`，
    
  按状态追玩家深度：CHASE 1.15 / WINDUP·ATTACK 1.90（出招时更凶地贴上来）/
    
  RECOVER·DEFEND 0.70 / IDLE 且玩家在 320px 内 0.55 / STAGGER·DODGE 保持。
    
  Boss 追得更稳（0.45），飞行敌人深度锁死。

**③ 战斗按「命线」判定**

- `main.gd` 新增 `_lane_ok(e)`：Boss 放宽到 0.85，杂兵用 `LANE_TOL = 0.30`。

## R11 · 架势交锋层（只狼内核接入）· 已实现（2026-10-27）

> 前置：R10 已稳定运行，`main.gd` 重建完成，`perfect_ready`（停手 ≥0.30s 首刀）已接入拼刀判定。
> 本轮不新增关卡/武器/遗物，只做一件事：**把“拼刀”升级为“架势交锋系统”**。
> 状态：代码已落地，`tools/selftest.gd` 全量回归 PASS=35 / FAIL=0（含 T31–T35），见 `自测记录_R11.log`。

### 为什么做这一层

当前玄界的拼刀是“一次性事件”：完美拼刀触发 → 获得收益 → 回到普攻。  
只狼的核心不是单次弹反，而是 **“普通格挡涨自己架势 / 完美弹反涨敌方架势”的双向倾斜**，  
让玩家在“安全但慢性死亡”和“冒险但扭转局势”之间持续做决策。  
没有这层，R12 的连招差异化和 R13 的圣物位次都缺少“战斗压力”的底座。

### 机制设计

| 机制 | 玩家行为 | 架势变化 | 结果 |
|---|---|---|---|
| **普通格挡** | 按住格挡键 / 非完美窗口防御 | 自身架势 **+18** | 低风险，但持续累积会崩条 |
| **完美弹反** | `perfect_ready` 为真时出刀迎击 | 自身 **+0**；敌方 **+40% 最大架势** | 高风险高收益，是打破僵局的主要手段 |
| **被击中** | 未格挡/未弹反 | 自身架势 **+25** | 鼓励玩家主动交锋而非龟缩 |
| **架势满（玩家）** | 任一来源使自身架势 ≥ 100 | 进入 **破绽** 1.2s，不可行动 | 不直接死亡；破绽期间受击额外扣 1 血（整数血制下近似 1.5×） |
| **架势满（敌人）** | 敌方架势 ≥ 100 | 进入 **破绽** 2.0s（Boss 1.2s） | 玩家可处决：造成 **当前血量 25%** 伤害（Boss 15%），并重置敌方架势 |

> 数值为初版，需在真机上调。完美弹反的敌方架势收益参考只狼“约 40% 躯干值”。
